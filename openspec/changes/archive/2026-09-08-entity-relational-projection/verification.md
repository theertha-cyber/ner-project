## 2. Hallucination Risk Register

For each area of complexity in this change, identify what an AI agent might get wrong
and how a human reviewer can detect and correct it.

| # | Risk Area | Potential AI Error | Human Check Required |
|---|-----------|-------------------|----------------------|
| 1 | Entity-type routing (design.md Decision 3) | Implementing routing as `entity.entity_type == definition.name`, or as a case-sensitive comparison. This compiles, passes any test written with fine-tuned fixtures, and silently produces **empty tables for every base-model tenant** — the failure looks identical to "no entities found" | Read the routing function directly. It must build its index from `entity_type_literals(definition)` and look up `entity.entity_type.strip().upper()`. Grep the projection module for `.name ==` and for any comparison against `definition.name` that is not routed through the helper. Confirm a base-model fixture (an entity with `entity_type = 'ORG'` and a definition whose `base_label_mapping` carries `ORG`) exists in the tests and fails when the helper is bypassed |
| 2 | Transaction boundary (design.md Decision 2) | Placing the projection call outside `with engine.begin() as conn:`, or opening a second connection inside the projection function, or emitting reconciliation DDL inside the per-document transaction because "the table might not exist" | Read `worker.py` around the existing transaction. All five operations — both deletes, both inserts, the projection — must be inside one `with engine.begin()` block, and the reconcile call must be before the document loop in its own transaction. Confirm the projection function takes the caller's connection rather than creating one |
| 3 | Delete-before-insert scope (design.md Decision 4) | Deleting `extracted_entities` along with the other two — it looks symmetric and tidy — which breaks `get_already_extracted` and makes every document eligible on every run. Or scoping `delete_relational_entities` to only currently-active definitions, leaving a deactivated definition's rows stranded | Grep the worker's transaction for any delete against `extracted_entities` — there must be none. Read `delete_relational_entities` and confirm it enumerates existing generated tables, not the active definition list |
| 4 | Drop-on-deactivation carried over (design.md Decision 5) | Preserving the foundation module's drop behaviour during the retarget, turning `DROP VIEW IF EXISTS` into `DROP TABLE IF EXISTS` as a mechanical translation. This destroys rows on a reversible flag | Grep `entity_views.py` and the reconciler for `DROP`. There must be none. Confirm `tests/test_entity_views_generator.py` and `tests/test_entity_views_reconciler.py` had their drop-on-inactive assertions replaced with a no-drop assertion, rather than merely retargeted |
| 5 | Single-value tie-breaking (design.md Decision 8) | Sorting by `confidence` alone, or using `max(entities, key=lambda e: e.confidence)`. Because `collapse_duplicates` sets confidence to the `min` of merged values, ties are common, and the selected value then depends on list order and changes between runs over identical input | Read the selection function. The sort key must be `(-confidence, -occurrence_count, normalized_value)`. Confirm a test feeds the same entities in two different orders and asserts the same selection |
| 6 | Typed-column fallback (design.md Decision 7) | Writing `entity.value_number or entity.entity_value`, or `COALESCE`-ing surface text into a typed column when parsing failed. This makes numeric comparisons silently wrong rather than empty | Grep the value-selection code for `or`, `COALESCE`, and any `str()` cast on a typed path. An unparsed typed value must produce `None`. Confirm a test asserts NULL rather than surface text |
| 7 | Grant/whitelist drift (design.md Decision 1, ADR-007) | Resolving the granted table set and `validate_sql`'s whitelist from two separate code paths — for example, adding generated tables to the grant list while leaving `WHITELISTED_TABLES` static — so a table is granted but rejected, or whitelisted but not granted | Trace both call sites back to a single resolver function. Confirm a test computes both sets for one schema and asserts equality for the generated tables, and that inactive definitions are excluded from both |
| 8 | Statement-builder duplication (design.md Decision 9) | Writing separate delete logic for the sync worker and the async document-delete endpoint because the session types differ, which drifts and leaves documents half-deleted | Confirm both callers import the same `build_relational_delete_statements` and only differ in how they execute. | 9 | Catalog configuration path (design.md Decision 11) | Wiring the projection while leaving `create_entity_type`'s INSERT column list untouched, so every entity type created through the UI carries a NULL `sql_identifier` and is skipped by the reconciler and the projection.
