## 2. Hallucination Risk Register

| # | Risk Area | Potential AI Error | Human Check Required |
|---|-----------|-------------------|----------------------|
| 1 | Substring / no-invention check (design Decision 6, step 3) | The check is implemented as a similarity or fuzzy comparison, or is applied against the model's *own* echoed text rather than the server-supplied window — either of which admits invented values while appearing to pass tests | Read the validation function. Confirm the comparison operand is the server-built window string, that the check is exact containment after canonical folding, and that no fuzzy/ratio/`in` on a model-supplied field is used. Add a case where the model returns a plausible but absent value and confirm it is discarded |
| 2 | Confidence calibration (design Decision 1) | Softmax applied over the wrong axis, or applied to already-normalized values, producing numbers in `[0,1]` that are not the predicted label's probability — the tests in rows 2–3 would still pass | Compare the implementation against a hand-computed softmax on a known logit vector. Confirm the axis matches the label dimension and that the value taken corresponds to `argmax`, not `max` of the softmax of a reduced tensor |
| 3 | `_is_adjacent` widening (design Decision 2, repair 2) | The page-equality condition is dropped or short-circuits when `page_number` is NULL, silently restoring the cross-page stitching this guard exists to prevent | Read the condition. Confirm different pages never merge, and that NULL page numbers fail closed (split) rather than open. Row 14 must have a test with NULL pages as well as differing pages |
| 4 | Fail-open policy (design Decision 8) | Only the happy path and the timeout path are implemented; rate limit, malformed response, and budget exhaustion fall through to a generic exception handler that marks the document failed and loses entities | Trace each of the five failure modes in rows 48–52 to a distinct code path. Confirm each persists deterministic entities. Confirm `failed_count` does not increment for post-processing failures |
| 5 | Provenance columns (design Decision 7) | Column names invented or renamed during implementation, or `source_entity_value` populated unconditionally — doubling storage and making "what changed?" unanswerable by a NULL check | Compare the migration's column list against the spec. | 6 | Dedup and citation fidelity (design Decision 3) | Collapsing implemented as `DISTINCT` at insert, discarding `occurrence_count`, or retaining an arbitrary rather than the first span — breaking the citation offsets ADR-007 depends on | Verify the first mention's span survives in document order (row 65), that `occurrence_count` is populated, and re-run the retrieval evaluation to confirm citations still resolve |
| 7 | Processing-mode enforcement (design Decision 10) | The worker reads a tenant setting or environment variable instead of the task argument, so a run's recorded mode and its actual behaviour diverge | Read the worker signature and body. Confirm the mode arrives as a task argument and that no settings lookup decides it. Test row 70 by changing the setting after dispatch |
| 8 | Entity-type correction scope (design Decision 5) | The `entity_definitions` membership check is case-sensitive or queries `public.entity_definitions` without the tenant filter, admitting another tenant's configured types | Read the lookup. Confirm it filters by `tenant_id` and matches case-insensitively, consistent with `load_entity_type_config` |
